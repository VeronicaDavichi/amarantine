# 管理台前端（M5）：需求待澄清

> **Status**: planned · **Priority**: medium · **Created**: 2026-11-03

## Overview

从 001 拆出来的遗留项。**它的第一件事不是写代码，是把需求问清楚。**

需求依据出奇地薄：

| 来源 | 说了什么 |
|---|---|
| `docs/P0-task-plan.md` M5 行 | 「前端能裁决与看报告」，验收指向 A12 / A31 |
| `docs/ADR-001-memory-architecture.md` | **全文中「前端」二字一次都没出现**，无任何前端设计章节 |
| ADR A12 | `POST /admin/forget/sweep` 的 `dry_run` 报告人工抽检 —— **纯接口** |
| ADR A31 | `memory_remember(pinned=true)` 后 `/admin/review` 不出现该卡 —— **纯接口** |

也就是说：M5 被写成「前端」，但它引用的两条验收**都已经被后端接口满足**
（`/admin/forget/sweep`、`/admin/review`、`/admin/label-review` 等 25 个端点全在）。
「前端」这个词在需求文档里没有承载任何具体内容。

所以本 spec 的交付物是**一份可拍板的需求**，不是页面。

**目标（二值判定）**

- B1 明确回答「P0 到底要不要前端」：要 / 不要，以及理由
- B2 若要，列出**最小可用**的页面清单（每页一个操作 + 一个验收断言）
- B3 若不建前端，说明现有接口如何满足 A12/A31，并把 M5 正式关闭

**非目标**

| 不做 | 理由 |
|---|---|
| 先选框架再想需求 | 需求没定就选 Vue/React，等于用技术栈倒推动机 |
| 复用后端 FastAPI 的模板 | 管理面是裁决工具，不是展示页；共用模板会把两件事绑死 |
| 本 spec 内写业务代码 | B1 没拍板之前，写任何前端代码都是猜 |

**文档依据（docs/ 扫描）**

| 文件 | 用途 |
|---|---|
| `docs/P0-task-plan.md` M5 | 唯一的需求来源（一行） |
| `docs/ADR-001-memory-architecture.md` A12 / A31 | 两条被「前端」引用的验收，实为接口级 |
| `docs/user-manual.md` | 现有 25 个管理端点的 curl 用法 —— 这本身就是个「无前端也能用」的证据 |

## Design

### 为什么这个 spec 以「问问题」为主

一个 spec 的价值是让下一步可执行。现在 006 的可执行下一步**不是**「搭脚手架」，
而是「确认要不要做」。把「要不要」伪装成「怎么做」，会写出一个没人验收的东西。

### 三个必须先拍板的问题（写在这里，等主人回答）

1. **谁来用？** 只有主人自己（那 curl + user-manual 可能够了），
   还是有别人要看不该看的原始记忆（那必须有权限与脱敏）？
2. **看到什么程度？** 「裁决」= 一条条点接受/拒绝（`label-review`），
   还是只要一个「误删率 < 5%」的报告数字（`forget/sweep` 已经给了）？
3. **不做前端的代价是什么？** 现在 25 个端点都有 curl 示例，
   以及 `harness/e2e_admin.py` 的端到端脚本 —— 不做前端，缺的到底是效率还是可见性？

### 若要做，最小切片的形状（候选，未拍板）

只做两个页面，其余全砍：

| 页面 | 操作 | 验收 |
|---|---|---|
| 复核队列 | 列 `/admin/review?bucket=NEED_REVIEW`，逐条 接受 / 拒绝 | 操作后该条从列表消失，且 `label-review/{event_id}/resolve` 有记录 |
| 误删率报告 | 展示 `/admin/forget/sweep` 的 `dry_run` 结果 | 页面上能读到 `candidates` / 抽检样本 / 误删率 |

「看报告」优先于「裁决」—— 因为裁决的替代成本低（curl 一条命令），
而报告的替代成本高（要自己算）。

## Notes

### 为什么把它从 001 拆出来

001 的里程碑表里 M2–M4 早已由 002–005 交付完成，只剩 M5 悬着。
一个「已完成 90% 但永远差一点」的主 spec 会让每次看板都产生一次判断成本。
拆出来之后：001 结项说实话（后端+MCP 全通），006 悬着也说真话（需求没定）。
**两个都说真话，好过一个含糊的「差不多完成」。**

### 依赖关系

`leanspec link` 在 0.3.0 里不存在（`rel` 报 `not yet migrated`），
所以 006 → 001 的父子关系只能在这里文字声明：**本 spec 是 001 的 M5 拆分项**。
