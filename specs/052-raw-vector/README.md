# 向量源换成原文 + 摘要转关键词，双命中

## Overview

[spec 051](../051-raw-quote-index/README.md) 把原文分词补进了 BM25（hit@5 0.367 → 0.550），
但**向量仍然只由摘要生成**（实测 P50 只有 17 字）。这是当前瓶颈的根：
窗口内 30 条原文的信息在向量空间里不存在。

**主人的方案**：向量吃原文、摘要转关键词、两路双命中。
在 279 张卡的池子里实测（60 样本，seed=7）：

| 路径 | hit@1 | hit@5 | hit@10 | MRR |
|---|---|---|---|---|
| A summary 向量（现状） | 0.417 | 0.517 | 0.550 | 0.465 |
| B **raw 向量** | 0.550 | 0.550 | 0.600 | 0.558 |
| C summary 关键词 BM25 | 0.367 | 0.500 | 0.583 | 0.432 |
| **D B+C 融合** | 0.533 | **0.667** | **0.717** | **0.591** |

**单路都不够，融合才有效**：C 单独比现状还差，B 单独只 +0.033，
但融合后 +0.150（+29%）。这正好说明两路互补（向量吃原文的信息密度，关键词吃摘要的信噪比）。

> ⚠ 上表池子 279 张（全库 4383），竞争弱 15 倍，**数字偏乐观**。
> 全库现实目标定 hit@5 ≥ 0.62。

## 硬约束：向量源不能混

同一个 collection 里若一部分卡向量由 summary 生成、另一部分由 raw 生成，
两种向量语义空间不同、**相似度不可比**，排序会失真。

所以只有两条路：

| 做法 | 说明 | 代价 |
|---|---|---|
| **A 全量重算**（采用） | 4383 张 × 2.5s ≈ 3 小时，一次性 | 期间召回质量波动 |
| B 新 collection 渐进 | 新建 `MemoryEventRaw`，两路向量融合 | 代码复杂度 +1 路 |

选 A：只有一次 3 小时，之后新卡写入时直接算 raw；不维护两套向量。

## Design

### 向量源：summary → 原文窗口

```
现在：vector = embed(summary)                      ← 17 字
改成：vector = embed(raw_text_of_window)           ← 约 780 字 / 30 条原文
```

文本构造复用 **spec 051 的两道闸**（`raw_text_index.filter_quotes`）：
营销长文、QQ 卡片 JSON 不进向量（否则噪声直接进语义空间）。

**空窗口兜底**：若一张卡的原文全被闸挡掉，退回用 `summary` 生成向量
（否则无法写入）。这种卡实测 23 张（0.5%）。

**长度上限**：`RAW_TEXT_INDEX_MAX_CHARS`（默认 4000）也适用于向量文本 ——
超长窗口截断，避免 embedding 服务 413 / 超时。实测去营销后 P95 = 2677。

### 摘要转关键词：保持并增强

`summary_tokens` 已经是 bigram 分词（spec 051 之前就有），BM25 已在用。
本 spec **不换 tokenizer**（换 jieba 抽词要改 schema + 重灌，收益未验证），
只保证它在融合里被正确加权。

### 检索：三条通道

```
query
 ├─ 向量（原文）        ← 本 spec 换源
 ├─ BM25（摘要关键词）   ← 已有 summary_tokens
 ├─ BM25（原文分词）     ← spec 051 已加 raw_text_tokens
        ↓
      RRF 等权融合（ADR C.B4）
        ↓
      → 动态 K
```

保留原文 BM25：它和向量虽然都吃原文，但一个是语义、一个是字面，
实测两者命中集不完全重合（池内 B 0.550 / 原文 BM25 0.518）。

### 写入与回填

| 来源 | 做法 |
|---|---|
| 新写入 | `remember_event` 的 `encode()` 入参从 `summary` 换成 `raw_doc` |
| 存量 | `harness/reembed_raw.py`：读 SQLite 原文 → 拼窗口 → embed → 覆盖对象向量 |

回填脚本要求：**幂等、可续跑、打印进度、失败单卡跳过**。
重算中途停掉不影响服务（老向量仍在，只是新旧混合期间排序略失真）。

## Notes

### 为什么先做池内实验再动手

卡级 raw 向量 2.5 秒/卡，全量 3 小时 —— 赌错方向代价太大。
池内实验 12 分钟就给出了方向性答案（+29%），这个顺序是对的。

### 不做什么

| 不做 | 理由 |
|---|---|
| 换 tokenizer 到 jieba 抽词 | 要改 schema + 全量重灌；当前 bigram 的 BM25 已达 0.500，先不动 |
| 一卡多向量（每条原文一个） | 实测每原文一向量可行（91ms/条，14 分钟），但那是 30 倍向量数；卡级融合已达预期，先不引入复杂度 |
| 同时保留 summary 向量 | 混合向量源不可比（见「硬约束」） |

### 2026-11-27 · 全量重算完成，**指标未达标**（如实记录）

**重算本身是成功的**：4379 张全写、失败 0、耗时 185.7 分钟。
- 用原文向量 4356 张 / 退回摘要 23 张（0.5%，符合预估）
- 抽检 12 张：`cos(stored, raw_embed) = 1.0000`，向量确实换成了原文

**但指标只涨了噪声级**（同批 60 样本，seed=7）：

| 指标 | 重算前 | 重算后 | 变化 |
|---|---|---|---|
| hit@1 | 0.417 | 0.433 | +0.016 |
| hit@5 | 0.550 | **0.567** | +0.017 |
| MRR | 0.456 | 0.483 | +0.027 |
| P50 | 1575ms | 1561ms | −14ms |

逐条：新增命中 2 条、丢失 1 条、一直命中 32、一直没中 25 → **净 +1 条**。

**D7 门槛 0.62 未达到**；也远低于池内实验的 0.667。**这次改动不能算成功。**

### 根因：卡级拼接稀释了语义

子代理做了全库纯向量测量（无 RRF、无闸门，4382 张参与排序）：

```
纯向量 hit@1 0.400 / hit@5 0.400
目标卡与 query 余弦：P10 0.465  P50 0.530  P90 0.655
< 0.5（被 RECALL_VECTOR_MIN_SIM 丢掉）：15/60 = 25.0%
```

**被闸掉的 15 条，纯向量 hit@1/hit@5 = 0.000；过闸的 45 条是 0.533。**

机制：原文向量是 **900–1200 字**拼成的一段，与**短 query**（十几个字）
算余弦时被稀释 —— 绝对相似度整体下移，1/4 的目标卡连候选都进不去。

**这正是本 spec 「不做什么」里划掉的那条方案（一卡多向量 / 每原文一向量）
要解决的问题。** 当时划掉的理由是「30 倍向量数、卡级已达预期」——
但池内实验的 0.550 在全库规模下**没有复现**（池内 279 张 vs 全库 4382，
竞争差 15 倍）。那个理由不成立了。

而且实测发现**每原文一向量反而更快**：
- 卡级（780 字/次）：2.6 秒/卡 × 4383 ≈ **3 小时**
- 每原文（20 字/次）：91ms/条 × 9112 ≈ **14 分钟**（短文本 embedding 快得多）

所以「30 倍向量数」这个代价判断也需要重估。

### 另外发现两个独立问题

1. **`recall()` 只返回 1–2 条材料**（实测 `materials=2/1/2`）。
   所以 `hit@10 ≡ hit@5` —— 分母是 60，但每条 query 只有 rank 1–2 可能命中。
   这意味着 0.62 门槛在当前返回条数下等价于「rank≤2 命中 62%」，非常苛刻。
   疑似 `RECALL_COUNT_MIN_SCORE=0.5` 在动态 K 阶段砍太狠（曾观测到一刀丢 40 个候选）。
2. **rerank 全程未生效**（`ReadTimeout` ×61）。基线与重算后都一样，所以对比公平，
   但分数是「无精排」状态下的。CPU 上 50 条要 5.6 秒 vs 800ms 预算，已知不可行。

### 结论

**卡级原文向量这条路收益不足。** 下一步候选（按性价比）：
1. **每原文一向量**（14 分钟灌 + 改检索映射）—— 直接针对稀释根因
2. 调 `RECALL_VECTOR_MIN_SIM` / `RECALL_COUNT_MIN_SCORE` —— 治「返回材料太少」，
   但绝对阈值对稀释后的向量不友好
3. 回滚到摘要向量（保留 051 的原文 BM25 那 +0.183 的收益）—— 保守选项

向量已经换成原文且指标不降（0.567 > 0.550、MRR +0.027、P95 −311ms），
**暂不回滚**，等方案 1 或 2 验证后再定。
