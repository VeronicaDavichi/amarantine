# 召回 hit@5 只有 0.37：它不是调参问题，是原文从未被索引

## Overview

主人让我「看下 hit@5 这个毛病」。复现 + 四层诊断后，结论与原判断不同：

**这个数字大部分不是排序链路的锅，而是「卡片只索引摘要，原文没有任何索引」。**

### 复现（60 条样本，seed=7）

```
hit@1  0.283 / hit@5  0.367 / MRR 0.329 / P50 276ms
```

评测口径：从 `raw_quote` 取一条真实消息当 query，目标是**由它建出来的那张卡**
（`raw_quote_ids` 反查）。这不是循环论证 —— 是「我记得有句话…」这个真实场景。

### 诊断 1 · 瓶颈在向量层，不在融合与精排

| 目标卡在向量层的名次（top50） | 样本 |
|---|---|
| 1–5 | 25（42%） |
| 6–50 | 6（10%） |
| **>50，找不到** | **29（48%）** |

最终 hit@5（0.367）≈ 向量层 hit@5（0.417）→ 后面的 RRF 融合、rerank、
动态 K 基本没损失什么。**改排序权重是白费力气。**

### 诊断 2 · 根因是卡片粒度：30 条原文 → 1 个话题摘要

每张卡由 **30 条**原文建成（实测 4383 张卡覆盖 9112 条原文），
摘要只写这 30 条里的**一个主要话题**：

```
原话：上厕所不冲厕所的吗！！！！
摘要：海嗣表示不觉得和妹妹之间谁占了便宜      ← 同一窗口，完全无关的话题

原话：哈哈被你认出来啦，我就是那条蓝发肥鱼～
摘要：西伯利亚大土豆表示自己整夜未睡，准备补觉
```

**量化**：60 条里 **54 条（90%）原话与目标卡摘要零内容交集**（字符 bigram Jaccard = 0）。

| 原话与摘要的 Jaccard | 样本 | 向量 hit@5 |
|---|---|---|
| 0（无交集） | 54 | 0.37 |
| 0 < J < 0.05 | 2 | 0.50 |
| J ≥ 0.05（摘要真的写了这件事） | 4 | **1.00** |

**摘要里写了这件事时，向量召回 4/4 全中。** 检索器本身没问题。

### 诊断 3 · 换检索方式救不了

| 方式（top50） | hit@1 | hit@5 | ≤50 命中 |
|---|---|---|---|
| 纯向量 | 0.333 | 0.417 | 0.517 |
| BM25（搜摘要） | 0.017 | 0.017 | 0.033 |
| 混合 alpha=0.7 / 0.5 / 0.3 | 0.333 | 0.417 | 0.517 |

BM25 近乎失效：摘要被 LLM 改写，与原话字词对不上。混合检索等于纯向量。
（第一版测出 BM25 全 0 是我把 GraphQL 对象键写成带引号导致的语法错，
已修正后重测，本表是修正后的数。）

### 诊断 4 · 真正的缺口：原文一条都没被索引

现有管道**已经有** BM25 通道，但它只搜摘要派生的字段：

```
_BM25_PROPERTIES = ("summary_tokens", "conclusion_tokens")
```

9112 条原文只存在 SQLite，**在向量库里没有任何可检索的表示**。

用内存倒排表模拟「如果索引原文」（bigram + IDF，取 top80 原文 → 映射到卡）：

| query 长度 | hit@1 | hit@5 |
|---|---|---|
| 原句全文 | 0.917 | **0.917** |
| 前半句 | 0.917 | **0.917** |
| 前 1/3 | 0.867 | **0.867** |
| **现状纯向量** | 0.333 | **0.417** |

两通道并集（任一命中）= **0.95**。

**必须说清的限定**：这些 query 本身就是语料原句，对关键词通道天然有利，
0.917 是**上界**。真实用户会换词，收益要打折。但「前 1/3 仍留 0.867」
说明只记得半句也够用 —— 而这正是「我记得有句话」这个场景。

## 这条推翻了 005 的一条非目标

[005 原文层](../005-raw-quote/README.md) 明确写：

> 原文参与召回：**不做**。理由：原文是溯源通道，不是检索材料；
> 进索引会污染召回评分的语义。

**它担心的事是真的**，所以本 spec 不是推翻它、而是绕开它：

- 005 拒绝的是「把原文塞进卡片一起索引」→ 会让 30 条消息的窗口变成一篇长文档，
  BM25 什么都能匹配，卡片语义被稀释。**这个拒绝是对的，本次不改。**
- 本 spec 做的是**独立通道**：原文单独一个 collection，检索命中后
  **映射回卡片**，卡片的向量与 BM25 分毫不动。

所以 005 的约束仍然成立，只是「不做」的范围收窄为「不混进卡片索引」。

## Design

### 走 010 的既有先例：独立 collection，不污染主表

[010 chunk 层](../010-chunk-dedupe/README.md) 已经用同样的手法解决过同类问题：

> 往同一个 collection 混入 chunk 会让**每一处**都得加 `is_chunk == false` 过滤，
> 漏掉一处就静默算错。独立 collection 的代价是「检索多查一次」，
> 收益是**现有路径一行不用改**。

本 spec 照抄这个决定：

```
MemoryRawQuote（新 collection）
  quote_id      text           ← 原文（已脱敏前的事实，来自 raw_quote 表）
  namespace     text
  parent_event_ids  text[]     ← 反查：这句原文建出了哪些卡
  text_tokens   text           ← 与现有 tokenize 同口径（bigram），供 BM25
  ts            date
  session_id    text
```

### 检索路径：新增第 4 路，只做「命中原话 → 映射到卡」

```
query
 ├─ 向量（卡片摘要）      ← 不动
 ├─ BM25（卡片摘要）      ← 不动
 ├─ 图（实体邻域）        ← 不动
 └─ 原文通道（本 spec）  ← 新：BM25 搜 MemoryRawQuote → parent_event_ids → 卡
        ↓
      RRF 融合（权重低于前三路，因为它「命中即强证据」但不该压过语义）
        ↓
      rerank → 动态 K
```

**权重为什么压低**：原文通道命中率高但语义窄（只证明「这句话出现过」，
不证明「这张卡在讲这件事」）。RRF 里给它较小权重，让它做**补漏**而不是主导。

`trace.channels` 新增 `raw_quote_hits` / `raw_quote_cards` 两个计数，
便于事后判断这一路到底贡献了什么。

### 写入路径：两处都要写

| 来源 | 做法 |
|---|---|
| `POST /admin/ingest` | 原文落 SQLite 时同步写 `MemoryRawQuote`（批量） |
| 存量数据 | `harness/reindex_raw_quotes.py`：从 SQLite 读 → 批量写，幂等（按 `quote_id` MERGE/覆盖） |

**不做启动时自动补齐**：4383 卡 / 9112 条原文的重灌会拖慢冷启动，
且失败会让人以为服务坏了。手动脚本 + `/health` 里一个明确的
`raw_quote_indexed: true/false` 提示，比自动跑更可控。

### 开关

`RAW_QUOTE_INDEX_ENABLED=false` 为默认（新功能默认关，零风险上线，
与 `CHUNK_ENABLED` 同口径）。关掉时行为与今天完全一致。

## Notes

### 为什么先建 spec 不动手

这是 **Weaviate schema 变更 + 存量 reindex**，属于会改变部署形态的改动。
而且它推翻了 005 的一条明确非目标 —— 这类决定要留痕，不能只在 commit 里。

### 也顺手修了「指标」这件事

`hit@5 = 0.37` 这个单一数字掩盖了两件完全不同的事：

- 摘要写了这件事 → 命中率 **1.00**（检索器很好）
- 摘要没写 → 命中率 **0.37**（缺通道）

只报一个总数，会让人误以为「检索器不行」，然后去调 rerank 权重 ——
方向错了。所以 T6 要求分档报告，这是**让指标说真话**，不是挑好听的数。

### 依赖关系

`leanspec rel` 在 0.3.0 里仍报 `not yet migrated to the adapter API`，
所以依赖只能文字声明（与 005 / 010 同样处理）：

- **[005 原文层](../005-raw-quote/README.md)** —— 本 spec 的**软依赖**：
  数据来自它的 `raw_quote` 表；同时本 spec 收窄了它的一条非目标（见上）。
- **[010 chunk 层](../010-chunk-dedupe/README.md)** —— **参照实现**，不是运行时依赖：
  独立 collection + 默认关闭开关的写法直接照抄。

### 不做什么

| 不做 | 理由 |
|---|---|
| 改卡片切分粒度（30 条 → 更小） | 要重灌全部语料 + 重跑 LLM 摘要，成本是另一个数量级；先做便宜的通道 |
| 让原文参与**卡片**的向量/BM25 | 005 的拒绝理由成立（长文档稀释语义） |
| 原文通道做向量检索 | 原文短、噪声大，关键词更稳；且省一次 embedding |
| 把摘要改成「列出多个话题」 | 也是重灌成本，且会拉长摘要、影响现有召回分布 |
