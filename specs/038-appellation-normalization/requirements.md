# 038 需求：称呼要落到真人，别名边要干净

> 父 spec：[README.md](README.md) · 设计：[design.md](design.md) · 任务：[tasks.md](tasks.md)

## 1. 缺陷现象

### 1.1 称呼被当成独立的人

灌入 `10000000001`（四人小群）后，图里同时存在：

```
王泳    88 条事件      ← 真人（他自己发的言、他的部署动作）
王老师   8 条事件      ← 称呼节点（任泽安对他的敬称）
两者之间：没有任何 ALIAS_OF 边
```

直接后果：问「前端开发是谁」时，`王泳` 与 `前端` **零共现**；而
`王老师` 与 `前端` 有 **2 张卡**（「要求王老师先更新测试环境前端」等）——
证据在库里，挂错了节点。

### 1.2 库里其实已经写明了别名

有一张卡的摘要就是：

> 任泽安称呼王泳为王老师

这是**显式的别名声明**，但系统没有建成边。

### 1.3 唯一的别名边还是脏的

```
接口 --ALIAS_OF{label:uncertain, conf:0.4}--> 任泽安说明
源卡片摘要：「任泽安说明就是这个接口」
```

`任泽安说明` 不是名字，`就是` 在这句里是叙述语气，不是等价声明。

## 2. 当前行为（WHEN / THEN）

- **WHEN** 文本写「称呼 X 为 Y」「叫他 Y」**THEN** 不产生任何别名声明。
- **WHEN** 文本出现 `A 就是 B` **THEN** 抽成别名声明——**无论 A/B 是不是名字**。
- **WHEN** 别名声明抽到 **THEN** 两侧名字只被并为 `Entity(kind="topic")`，
  不建立 `ALIAS_OF` 边、不指向 `Person`。
- **WHEN** 称呼（王老师/刘老师/陈总）出现在摘要里 **THEN** 会被独立抽成 `Person`。

## 3. 预期行为（WHEN / THEN SHALL）

- **REQ-1** **WHEN** 文本含称呼声明（`称呼X为Y` / `叫X为Y` / `X（Y）` / `X 是 Y 的称呼`）
  **THEN** 系统 SHALL 产出别名声明 `alias=Y, canonical=X`。
- **REQ-2** **WHEN** 别名声明两侧都是**已知真人**（`Person` 节点或名册成员）
  **THEN** SHALL 建立 `(Y)-[:ALIAS_OF {label:"exact"}]->(X)`，并让 Y 名下的事件可通过
  X 检索到（`INVOLVES` 边不被移动，查询侧走别名展开）。
- **REQ-3** **WHEN** 别名声明的一侧不是名字（`任泽安说明` / `这个接口`）
  **THEN** SHALL 拒绝建边，并按 002 的机制写入 `alias_reject` 留痕。
- **REQ-4** **WHEN** 抽取在**卡片摘要**（第三人称叙述）上运行时
  **THEN** SHALL 比在用户原话上更严格（至少要求两侧都是干净名字），
  防止「说明就是这个接口」这类句式误抽。
- **REQ-5** **WHEN** 图上已存在脏别名边（如 `接口 → 任泽安说明`）
  **THEN** 系统 SHALL 提供清理手段（按 reason 批量删除 `ALIAS_OF`）。

## 4. 不变行为（回归防护）

- **WHEN** 用户原话说「糖包就是豆包」**THEN** SHALL CONTINUE TO 建出 `exact` 边（002/003 的正例）
- **WHEN** 判据不通过 **THEN** SHALL CONTINUE TO 写 `alias_reject` 且不阻断记忆写入
- **WHEN** 名册注册 **THEN** SHALL CONTINUE TO 最长匹配优先（035）
- **WHEN** `accepted` 补边 **THEN** SHALL CONTINUE TO 走 `force=True`，不重新判据（003）
- **WHEN** 英文缩写抽取 **THEN** SHALL CONTINUE TO 不受影响（037 落地后）

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 成本 | 称呼解析是纯正则，不新增 LLM 调用 |
| 召回 | 别名展开最多 1 跳（`ALIAS_OF` 不传递闭包，避免链式误连） |
| 可观测 | 每次拒建边写明 reason（复用 002 的 `alias_reject`） |
| 可修 | 脏边可按 `reason` + `label` 批量清理，不碰正常边 |

## 6. 非目标

| 不做 | 理由 |
|---|---|
| 用 LLM 推断「谁是王老师」 | 已有显式声明，规则层够了；推断只覆盖声明缺失的场景，另开 |
| 把 `INVOLVES` 边搬到真人名下 | 破坏原始证据；查询侧做别名展开更可逆 |
| 处理「今天下午」「道谢」这类非人噪声 | 属于抽取通道的另一个问题，避免本 spec 失焦 |
| 称呼的跨群消歧（两个「王老师」指不同人） | 需要名册 + 部门信息，单开 |
