# 身份来源分层：uid > 备注 > 昵称 > 姓名，短名字优先

> **Status**: planned · **Priority**: high · **Created**: 2026-11-06

## 目标

把「这是不是一个真人、叫什么」从**词形猜测**改成**账号数据准入**：

```
uid（身份锚，跨群稳定）> 备注（人手工写的真名/说明）> 昵称 > 通讯录真名 > jieba
```

同时解决短名字（两字昵称占 **150/469 = 32%**）和「备注带说明」的解析。

## 执行顺序

```
043 身份来源（本 spec） → 038 称呼归一 → 041 指称层 → 042 账号族
```

本 spec 是这一串的起点：**先有权威身份，后面的归一 / 义项 / 归并才有可靠的锚**。
038 依赖它产出的 `uid → Person`；041 把「称呼」泛化成「指称」；042 再做账号族归并。

## 现状（一句话）

035 已经把「名册」升级为身份准入，但名册只用了**昵称**；
`uid` 没有成为实体主键，`备注/别名` 完全没用上（实测备注字段为空，需补采集）。
