# 关系谓词：从「事件牵涉了谁」到「谁和谁是什么关系」

> **Status**: draft · **Priority**: medium · **Created**: 2026-11-06

## Overview

**问题**：图上的关系只有挂载式边，没有谓词。

```
节点：Event 740 · Entity 41 · Person 40
边  ：RELATED 12640 · INVOLVES 848 · AT 743 · ACTION 92 · MENTIONS 91 · ALIAS_OF 1
人 → 人 的边：0
人 → 非 Event 的边：0
```

问「王泳跟谁对接」「谁负责前端」，**没有边可走**，只能靠共现猜。
而 `RELATED` 占了全部边的 92%（平均每事件 17 条），关系预算花在了事件纠缠上。

**目标**：定义业务谓词表，用**两条通道**把关系落成边：

| 通道 | 来源 | 强度 | 例 |
|---|---|---|---|
| **陈述** | 原话直接说 | `exact`（用户断言） | 「王泳负责前端」「成善维护 ESB」 |
| **行为** | 行为聚合推断 | `probable`（≥N 次证据） | 王泳部署前端 3 次 → 推断他维护前端 |

两条都需要：**陈述精确但稀疏，行为稠密但要推断**。缺任何一条都不够 ——
现在语料里陈述几乎为 0，全靠行为；将来有分工说明的群，陈述会补上。

**非目标**

| 不做 | 理由 |
|---|---|
| 引入推理机（RDFS/OWL/Datalog） | 缺的是边不是推理；触发条件见 Notes |
| 改事件卡粒度 | 卡的精度是 P0 已定项，上下文走窗口输入而不是塞进卡 |
| 跨 namespace 合并实体 | 不在本 spec 范围 |

## Design

### 一、谓词表（v2，删掉了没证据的）

| 谓词 | 头 | 尾 | 陈述通道例子 | 行为通道候选动词 |
|---|---|---|---|---|
| `OWNS` | Person | Entity/Project | 「王泳负责前端」 | 改 / 修复 / 实现 / 加字段 |
| `MAINTAINS` | Person | Entity/Service | 「成善维护 ESB」 | 部署 / 发布 / 重启 / 更新 / 回滚 |
| `COLLABORATES_WITH` | Person | Person | 「他和刘岳一起弄」 | 同一事件里共同 `INVOLVES` |
| `DEPENDS_ON` | Entity | Entity | 「aml-scripts 依赖中登接口」 | 接口文档/调用记录（待定） |

**删掉 `REPORTS_TO`**：实测 `汇报/上级/领导/主管` 在 566 条原文里 **0 命中**，
按「没有证据就先不定义」的规矩移除。将来语料里有再补。

### 二、陈述通道（精确）

**输入**：卡片摘要 + 上下文窗口（21 条，stride 10，50% 重叠）。

**为什么需要窗口**：关系常跨句 ——「王老师那边」+「他负责前端」两句合起来才成立。
窗口让抽取器看得到完整语境；重叠部分由 `MERGE` 吸收，不会重复建边。

**输出**：`(h)-[:PRED {label:"exact", confidence:1.0, evidence:[…]}]->(t)`

**护栏**（沿用 038 的教训）：摘要里的「就是」是叙述谓语，不是等价断言；
同理，陈述抽取也要区分「X 负责 Y」与「X 说明 Y 负责 Z」——后者要落到 Z 身上，不是 X。

### 三、行为通道（稠密）

**输入**：已有的行为边，不需要新语料。

```
(Person)-[:INVOLVES]-(Event)-[:ACTION]->(Action {verb:"部署"})
                              └-[:MENTIONS]->(Entity {name:"前端"})
```

聚合规则：

| 步骤 | 规则 |
|---|---|
| 1 取数 | 按 `(person, verb, target)` 分组，`count(distinct event_id)` |
| 2 动词映射 | `部署/发布/更新/重启` → `MAINTAINS`；`改/修复/实现` → `OWNS` |
| 3 阈值 | `count >= 2` 才算 `probable`；1 次只记证据不建边 |
| 4 衰减 | 只看 `RECENCY_WINDOW`（默认 90 天）内的事件；超期证据不计入 |
| 5 幂等 | 重跑按 `(h,p,t)` `MERGE`，`evidence` 数组按 `event_id` 去重追加 |

**为什么阈值 2 而不是 1**：部署一次可能是临时帮忙；两次以上才像「职责」。
这条阈值必须可配，并用金标校准（A5）。

### 四、两条通道怎么合并

```
MERGE (h)-[r:PRED]->(t)
SET r.label = CASE
      WHEN r.label = 'exact' THEN 'exact'          // 陈述永远不会被行为降级
      ELSE $label                                  // 行为按阈值给 probable
    END,
    r.evidence = <按 event_id 去重后的并集>,
    r.evidence_count = size(r.evidence),
    r.first_seen = min(...), r.last_seen = max(...)
```

**优先级**：`exact`（陈述）> `probable`（行为）。
行为通道**可以给已有陈述边加证据**，但永远不能把 `exact` 降成 `probable`。

**冲突**：陈述说 A 负责、行为指向 B → 两条边都保留，标 `conflict`，进人工队列。
不自动二选一 —— 和 043/038 的口径一致：判不准就留痕。

### 五、查询语义（接 041 的三档）

| 档 | 边集 | 场景 |
|---|---|---|
| `strict` | 只 `exact` | 「谁正式负责 X」 |
| `default` | `exact + probable` | 日常问答，命中标「推断」 |
| `explore` | 全含 `evidence_count` | 「谁可能碰过这个」 |

### 六、与其它 spec 的耦合

| spec | 关系 |
|---|---|
| 038 称呼归一 | 已完成：抽出来的人名不再落到假人节点 |
| 041 指称层 | 谓词边将来也要带 scope（项目/系统域），否则「前端」跨项目冲突 |
| 044 实体证据降级 | 行为通道的「目标实体」依赖它的 topic/降级规则 |
| 040 导入工具 | 窗口参数与它共用（导入时按窗口切分） |

## Notes

### 为什么两条通道都要（2026-11-09 核对）

实测 566 条原文：

| 类别 | 命中 |
|---|---|
| 关系陈述（负责/维护/对接/汇报/上级/负责人） | **0** |
| 行为（部署 11 · 确认 7 · 看一下 7 · 提供 3 · 截图 3） | 有 |

**只做陈述**：现有语料一条边都抽不出来（A1 的老版本就是这么不可达的）。
**只做行为**：能补出边，但都是推断，回答「谁**正式**负责」时没有事实可依；
而且临时帮忙（部署一次）会被误判成职责。

所以：陈述给**事实**，行为给**覆盖**，两者合并才是可用的关系层。

### 窗口参数的现状

`21 条 / stride 10` 是当初为「跨句陈述」定的，**至今没有验证过**。
行为通道不需要窗口（它按事件聚合）；陈述通道才需要，等有陈述语料再校准。

### 为什么暂不引入推理机

短答：**缺的是边，不是推理**。推理机的输入是已知事实，而现在人-人边为 0。

现在的三类「推理」，两类用 Cypher 就够：

| 需求 | 手段 |
|---|---|
| 路径/传递（别名、上级链） | `[:ALIAS_OF*0..1]`、`shortestPath` —— Neo4j 原生 |
| 写入期物化（同项目=>协作者） | 定时 Cypher 落成边 |
| 类型包含 / 一致性 / 可解释 | 这才需要推理机 |

**引入触发清单**（中三条再谈）：

1. 规则需链式组合且频繁变化，Cypher 维护不动
2. 多来源实体合并需要冲突检测
3. 查询里大量「间接关系」（间接汇报/持股/依赖）
4. 需要解释「结论由哪些规则推出」（审计场景）
5. 关系类型 > 50 且存在类型层级

ADR-001 对别名已表态：*「用户直接给了等价关系，不用推理」「别名表是可复查的事实，模型推理不是」* ——
引入推理机等于反转这个取向，得有强理由。

### 已定与未定（2026-11-09 更新）

**已定**

| 项 | 决定 |
|---|---|
| `REPORTS_TO` | **删除** —— `汇报/上级/领导/主管` 在 566 条原文里 0 命中 |
| 边的时间性 | 陈述**永久**；行为按 `RECENCY_WINDOW`（默认 90 天）衰减 |
| 谓词表要几层 | **暂不定层** —— 先按双通道把 4 个谓词跑通，分层等有真实数据再说 |
| 现有数据 | **清空重灌**，不在旧图上做迁移/清理/金标 |
| `RELATED` 12640 条 | 重灌后再看还剩多少再决定（很可能新写入路径就不再产生这么多） |
| `COLLABORATES_WITH` 证据口径 | **延后判断** —— 等重灌后看效果（「同一事件共同出现」可能太松） |

**未定**

- 行为通道的动词映射表要覆盖多少动词 —— T1 先用 6 个高频（部署/发布/更新/重启/改/修复）
- 谓词边的 scope（项目/系统域）—— 依赖 041，本轮不做
