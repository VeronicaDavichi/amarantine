# 断崖阈值与 RRF 分数尺度不匹配，把材料截到 1-2 条

## Overview

**这不是新功能，是修一个一直存在的参数错误。**

诊断「为什么 recall 只返回 1–2 条材料」时发现：20 条 query 累计
`min_score` 砍掉 2368 个候选（79%），而**`gap_ratio=0.15` 把最终结果断在 1–2 条**。

于是 `hit@10 ≡ hit@5` —— 每条 query 只有 rank 1–2 可能命中，
`hit@5` 实际上退化成「hit@1.5」。

### 根因：阈值和分数尺度不匹配

`RECALL_GAP_RATIO=0.15` 的含义是「相邻名次分差超 15% 就截断，认为后面都不相关」。
但 RRF 融合后的分数形状是 `1/(60+rank)`：

| rank | RRF 原始分 | 相对 rank1 的降幅 |
|---|---|---|
| 1 | 0.01639 | — |
| 2 | 0.01613 | 1.6% |
| 5 | 0.01538 | 6.2% |
| 10 | 0.01429 | 12.8% |
| **15** | **0.01333** | **18.7%** |

**从第 10 名往后，相邻降幅天然就超过 15%** —— 断崖检测几乎每次查询都触发，
把材料截在 1–2 条。0.15 这个值不是为 RRF 分数定的（RRF 后来才接入）。

## 实测

60 样本，3 个 seed，rerank 关（CPU 上不可行），同批数据只改 `gap_ratio`：

| seed | gap=0.15 | gap=0.35 | Δ |
|---|---|---|---|
| 7 | 0.567 | **0.667** | +0.100 |
| 11 | 0.567 | 0.617 | +0.050 |
| 23 | 0.500 | 0.600 | +0.100 |
| **平均** | **0.544** | **0.628** | **+0.083** |

**`hit@1` 在三个 seed 上完全不变**（0.433 / 0.483 / 0.367）——
说明只是把该给的材料给出来，**没有放进噪声**。

材料均从 4.8–6.2 涨到 8.9–10.7 条。

### 为什么取 0.35 而不是更大

扫描曲线（seed=7）：

| gap_ratio | hit@5 | 材料均 |
|---|---|---|
| 0.15 | 0.567 | 4.8 |
| 0.25 | 0.600 | 7.0 |
| **0.35** | **0.667** | 8.9 |
| 0.50 | 0.667 | 9.0 |
| 1.00（关闭） | 0.667 | 9.0 |

0.35 就触顶，再宽收益为零。取 0.35 保留断崖检测的**保护作用**
（真出现极异常分布时仍能截断），而不是干脆关掉。

## Design

### 为什么是参数错误而不是设计取舍

`RECALL_GAP_RATIO` 的设计意图是对的：**检测断崖**，避免把明显不相关的
尾部材料塞给 LLM。ADR 里这叫「断崖截断」，是防止「矮子里拔将军」的手段。

错误在于**阈值的量纲**：0.15 是给「归一化后接近均匀分布」的分数定的，
而实际喂进来的是 RRF 的 `1/(60+rank)` —— 一条长尾极缓的曲线。
同一个 0.15 在这两种分布上含义完全不同。

### 修改

只改默认值，不改算法：

```python
RECALL_GAP_RATIO: float = 0.35   # 原 0.15
```

保留断崖逻辑的好处：真出现「第 1 名 0.9、第 2 名 0.2」这种极端分布时，
它仍会正确截断（降幅 78% 远大于 35%）。

## Notes

### 这个发现纠正了我的方向性错误

我为了提召回质量，花 3 小时把向量从摘要换成原文，得到 **+0.017**（噪声级）；
而改一个**一直写错的参数**得到 **+0.083**，零成本、零风险。

教训：**先确认瓶颈在哪一层，再动手**。我当时看到「向量层丢了 48%」
就直接去改向量源，但没问「向量层丢了之后，就算找回，还有多少能活到最终结果」——
答案是：`gap_ratio` 会把它们再砍掉一大半。

### 与 spec 052 的关系

052 把向量源换成了原文窗口（卡级），指标只 +0.017。本 spec 的 gap 修正**独立于它**，
两者叠加后 hit@5 = 0.628（3 seed 平均）。

052 的结论保留：卡级原文向量不差（0.567 vs 摘要 0.550），但收益有限。
真正的根因在**卡片粒度**（30 条一刀切，内容太杂），另案处理。
