# 018 时间解析置信度分级：让 `TIME_CONF_MIN` 有真实语义

## Overview

spec 015 把 `TIME_CONF_MIN` 接到了 recall 的时间过滤器上，但留了一个尾巴：

> 当前 `DateRange.confidence` 只有 `0.0` 和 `1.0` 两个值，
> 所以默认 0.5 时**没有任何行为变化**。

本 spec 补上分级，让这个配置项第一次拥有真实的调节范围。

### 现状：所有「能解析」都给 1.0

`time_resolver.resolve_date_hint` 的 14 个返回分支里：

- 12 个用 `HIGH_CONFIDENCE = 1.0`
- 3 个用 `FALLBACK_CONFIDENCE = 0.0`（解析不出）

`HIGH_CONFIDENCE` 里混着两类完全不同的东西：

| 类型 | 例子 | 窗口边界 |
|---|---|---|
| **精确** | `2026-11-04`、`2026年3月`、`今天`、`昨天` | 算出来的，没有猜测 |
| **明确** | `上周`、`上个月`、`去年`、`本周` | 边界由日历定义，可复现 |
| **推算** | `上个月底`、`去年底`、`年底` | **窗口宽度是代码里拍的常数** |

第三类伪装成第一类：

```python
if text in ("上个月底", "上月底", "月末"):
    end = _month_end(last_month)
    return DateRange(end - timedelta(days=9), end, HIGH_CONFIDENCE, text)
    #                      ^^^^^^^^^^^^^^^^^^ 9 天是哪来的？拍的
```

`去年底` 更宽：`10-01 ~ 12-31`，111 天（这是**有测试保护的故意设计**，
见下文「非目标」）。

**「9 天」和「111 天」都不是从用户表达里推导出来的**，是开发者选的数。
这类结果的置信度不该是 1.0。

## 非目标

### 不改「去年底 = Q4」的窗口宽度

`tests/test_time_resolver.py::test_last_year_end_is_q4` 明确断言
`(2025-10-01, 2025-12-31)`，注释写「按 Q4 处理，不缩到单月」。

这是**设计选择**（「底」可能跨月，缩到单月会漏），不是 bug。本 spec 不动它。

### 不改精确/明确类的置信度

它们就该是 1.0。给「昨天」降置信是错的 —— 它的边界完全确定。

### 不改 `resolve_from_query`（整句抽取）

只改 `resolve_date_hint` 的置信度，抽取逻辑不动。

## Design

### D1 三档常量

```python
HIGH_CONFIDENCE = 1.0        # 精确/明确：边界可由日期直接算出
APPROX_CONFIDENCE = 0.6      # 推算：窗口宽度是代码里的常数
FALLBACK_CONFIDENCE = 0.0    # 解析不出
```

`0.6 > TIME_CONF_MIN(0.5)` 是**刻意的**：

- 默认配置下「上个月底」仍然设过滤器 → **默认行为不变**
- 把 `TIME_CONF_MIN` 调到 0.7 时「底」类被挡掉 → **配置第一次真的有用**

如果取 0.4，默认就会改变行为（「上个月底」退回全库），
那是本 spec 不该偷偷做的产品决定。

### D2 「底」类改用 `APPROX_CONFIDENCE`

两处：

| 行 | 表达 | 现行窗口 |
|---|---|---|
| 122 | `上个月底` / `上月底` / `月末` | `end-9天 ~ end` |
| 132 | `去年底` / `上年底` / `年底` | Q4（10-01 ~ 12-31） |

### D3 顺手修一个真 bug：`年底` 返回的是去年

`text in ("去年底", "上年底", "年底")` 共用分支，`y = today.year - 1`：

```
2026-11-04 说「年底」
  实际返回 2025-10-01 ~ 2025-12-31   ← 去年
  应该返回 2026 年年底
```

「年底」单独说时指的是**今年**年底，只有「去年底」「上年底」才是去年。

**为什么本 spec 必须修它**：如果不修，`年底` 会被标成 `APPROX_CONFIDENCE=0.6`
却仍然返回去年的数据 —— 那是**用低置信标签掩盖一个确凿的错误**，
比不给置信度更糟。分级的前提是「返回的窗口至少是对的」。

修法：拆成两个分支，`年底` 用 `today.year`。

窗口宽度沿用 Q4（与 `去年底` 保持一致，不引入新的猜测）。

## Notes

### 为什么是 0.6 而不是 0.4

`TIME_CONF_MIN` 的默认值是 0.5。选 0.6 让「底」类**刚好过线**：

- 保守：不改变任何现有行为，用户升级后感受不到差异
- 但配置项第一次有了真实的调节区间（0.5 < x ≤ 0.6 之间调都能区分两类）

如果选 0.4，「上个月底」在默认配置下就会退回全库 —— 那是产品决策，
应该用户拍板，不该藏在「分级」这个技术动作里。

### 015 埋的钩子如期生效

spec 015 里写了：

```python
def test_real_resolver_confidence_is_binary():
    """当前 time_resolver 只会给 0.0 或 1.0。这条不是保护行为，是记录现状。"""
    ...
    assert seen <= {0.0, 1.0}, f"置信度出现中间值 {seen} —— 015 的 Notes 需要更新"
```

本 spec 一改就会挂。**这就是元测试的价值**：它不保护行为，它提醒下游契约变了。

挂掉之后要做的两件事：
1. 更新这条测试（改成断言三档）
2. 回 `specs/015-time-confidence-floor/README.md` 的 Notes 补一句「分级已由 018 完成」

### 还有哪些表达值得单独考虑（未做）

| 表达 | 现状 | 可能的改进 |

| `上个月底` 的 9 天 | 常数 | 可配置化（`TIME_END_WINDOW_DAYS`），但只有一个用途，暂不抽 |

这些都是「给一个猜的窗口 vs 全库」的取舍，需要真实查询数据支撑，
不在本 spec。

### 一个观察：`月底` 与 `上个月底` 同义

`text in ("上个月底", "上月底", "月末")` 把「月末」也当成上个月底 ——
但「月末」在 2026-11-04 说，可能指**本月末**（11月30日），而不是 10 月末。

这是个潜在的语义 bug，但「月末」这个说法本身有歧义（口语里常指「这个月月末」
也可能是「每个月的月末」）。没有测试保护，也没有真实用例。

记录但不改 —— 需要先确认用户实际怎么用这个词。

## 实现记录

### 分级结果

| 档 | 值 | 表达 |
|---|---|---|
| 精确/明确 | 1.0 | `2026-11-04`、`2026年3月`、`今天`、`昨天`、`前天`、`本周`、`上周`、`本月`、`上个月`、`今年`、`去年` |
| 推算 | 0.6 | `上个月底`、`上月底`、`月末`、`去年底`、`上年底`、`年底` |
| 解析不出 | 0.0 | 其他 |

分类判据不是「是否依赖 today」（那样 `昨天` 也会被降级，错的），
而是**窗口宽度从哪来**：

- 从日历定义算出来 → 1.0
- 从代码里的常数拍的（10 天 / Q4）→ 0.6

### 顺带修的真 bug：`年底` 返回去年

```
修复前（2026-11-04 说「年底」）：2025-10-01 ~ 2025-12-31   ← 去年 Q4
修复后：                        2026-10-01 ~ 2026-12-31   ← 今年 Q4
```

原因是 `text in ("去年底", "上年底", "年底")` 共用一个分支，`y = today.year - 1`。
拆成两个分支即可。

**为什么本 spec 必须修它而不是「记录后单独开 spec」**：
如果不修，`年底` 会被标成 0.6 低置信却仍然返回去年的数据 ——
那是**用低置信标签掩盖一个确凿的错误**。分级的前提是「返回的窗口至少是对的」。

窗口宽度沿用 Q4，没有引入新的猜测。

### 不改「去年底 = Q4」

`test_last_year_end_is_q4` 明确断言 `(2025-10-01, 2025-12-31)`，
注释写「按 Q4 处理，不缩到单月」。这是**设计选择**（「底」可能跨月），
不是 bug。只给它补了置信度断言。

### 为什么 0.6 而不是 0.4

`TIME_CONF_MIN` 默认 0.5：

- 0.6 → 默认**过线**，行为不变；调到 0.7 就能单独挡掉推算档
- 0.4 → 默认就被挡掉，等于偷偷改变行为

「让推算档在默认配置下退回全库」是**产品决策**（会改变召回宽窄），
不该藏在「分级」这个技术动作里。选 0.6 只给配置一个真实的旋钮，不动默认行为。
